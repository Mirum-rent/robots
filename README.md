# Роботы — Дмитрий Рыбак

Четыре проекта и метод разработки с ИИ: **DARNeuroX, DARTherapeX, DARCardioX, Koshka**. В портфолио показаны архитектурные задачи, датированные доказательства и отдельный небольшой работающий демонстратор.

Мой вклад — требования и алгоритмы, структура и границы, декомпозиция, диагностика, координация ИИ и приёмка результата. Это описание роли владельца; наличие рабочих документов подтверждено чтением источников, аудит авторства каждого коммита не проводился. Реализация и независимые проверки с помощью ИИ требуют технической верификации, как и любая разработка.

## Один запускаемый технический сценарий

Запрос мог быть принят, но ответ потерялся. Оригинальный демонстратор сохраняет намерение в SQLite до отправки, переживает перезапуск, блокирует слепой повтор, сверяет ключ и содержимое, обрабатывает повтор квитанции и отказывается работать с повреждённым состоянием. Все операции — *синтетические записи*, имитатор вызывается внутри процесса; сети, счетов, торговых сигналов и настоящих заявок нет.

Нужен Python 3.12+ со стандартной библиотекой; проверено на 3.12.14. Выполнять из корня этого комплекта:

```text
python -B -m demo.run
python -B -m unittest discover -s demo/tests -v
python -B -m demo.checks --output demo-output
```

Прогон 2026-10-15T21:24:37+03:00: **31 тест, 0 failures/errors/skips**, **5 CLI-сценариев PASS**. Отдельно измерены 211/213 исполняемых строк (**99.06%**) в `demo/core.py` и `demo/fake_api.py`, Python stdlib trace/dis; BRANCH не измерялось. Это только метрики нового демо. [Машинный отчёт](demo/reports/coverage.json) связывает их с SHA256 исходников.

Браузерная кнопка воспроизводит сохранённую запись этого прогона и не исполняет Python. Случай «нет квитанции» считается NOT_ACCEPTED только потому, что локальный fake полностью согласован; для реального API такой вывод в общем случае недопустим. Это компактная последовательная демонстрация, не производственная система exactly-once.

## Как организована работа с ИИ

Человек задаёт продуктовые решения и критерии. Око Бога анализирует отчёты и направление работы; Супервизор декомпозирует; Аудитор готовит воспроизводимые задания и проверяет; Исполнитель реализует; Секретарь сохраняет контекст. По задаче добавляется инженер. Обмен между разными ИИ координирует Дмитрий, часть инструментальных действий автоматизирована. Codex, DeepSeek, ChatGPT и опыт использования кода Claude — инструменты этого процесса.

Кодекс, Вводные ролей, ТЗ, паспорта, журналы и реестры позволяют восстановить текущую задачу при смене чата. «Капча» проверяет понимание задания и границ до исполнения; «Совещание» обозначает обсуждение без действий. Независимая проверка другим ИИ дополняется исходниками, логами и тестами и не обещает безошибочность.

## Границы открытого комплекта

Здесь находятся новая витрина, обезличенные описания, реестр происхождения и новый демонстрационный код. Оригинальные торговые ядра, конфиги, параметры, сырые логи, суммы, идентификаторы и история Git исходных проектов исключены. Лицензия от имени владельца не назначена. См. [границы](docs/boundaries.md).

SHA256 закрытого источника идентифицирует снимок, но не делает его доступным читателю. Публичная часть позволяет воспроизвести именно демо и проверить согласованность его отчётов; показатели реальных проектов подтверждены перечисленными закрытыми материалами. Исходные проекты и тяжёлые наборы тестов при подготовке портфолио не запускались.
